# guidelines

このフォルダは、ゲーム実装のルール・手順・判断基準を置く場所です。

`guidelines` は、このゲームだけでなく、他のプロジェクトにも流用できる内容を蓄積するためのフォルダです。

この検証開発の目的の一つは、`guidelines` を作成・拡充し、精度を上げることです。新しくゲームを作る時、このフォルダをコピーすれば、一定品質の実装・レビュー・デバッグ手順を引き継げる状態を目指します。

## 置くもの

- コーディングルール
- 命名規則
- デバッグ方法
- Unity / C# / GitHub / SourceTree などの使い方
- レビューガイドライン
- セルフレビュープロンプト
- 実装前チェックリスト
- 実装後チェックリスト
- AIに作業させる時の指示テンプレート

## 置かないもの

- このゲーム固有の仕様
- 戦闘システムそのものの仕様
- アイテムやゴールドなどのゲーム内ルール
- キャラクターや世界観の仕様
- ロードマップや作業順序

それらは `docs/design/` または `docs/roadmap/` に置きます。

## 判断基準

別のゲーム開発でもほぼそのまま使えるなら `guidelines` に置きます。
このゲームでしか意味を持たない仕様なら `design` に置きます。
実装順序や作業単位なら `roadmap` に置きます。

## 例

```text
1つの修正では、既存挙動を壊さないことを最優先する
Unity側の設定手順も必ず記録する
C#エラー確認後にgit commitする
大きい実装は phase と task に分ける
```

上記は実装ルールなので、このフォルダの対象です。
