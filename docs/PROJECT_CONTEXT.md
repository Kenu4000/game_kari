# game_kari Project Context

## 概要

Unityで制作中の戦闘特化型RPG。マップ探索は作らず、拠点 → クエスト選択 → 会話イベント → 複数戦闘 → リザルト → 拠点、という構成にする。

主軸は、戦闘UIと4vs4の陣形型コマンドバトル。

## Unity方針

- Unity使用
- マウス操作のみ
- コントローラー操作は想定しない
- 基準解像度は1920x1080
- 最初は16:9固定
- UIはuGUI + TextMeshPro想定
- Canvas Scalerは `Scale With Screen Size`
- Reference Resolution は `1920 x 1080`

## 戦闘システム概要

- 4vs4のコマンドバトル
- 敵味方それぞれ2×2マス
- 味方には控えキャラあり
- 味方キャラ総数は6人程度を想定
- 行動順はターン開始時に盤面上の敵味方を素早さ順に並べる
- そのターン中に素早さが変わっても順番は変えない
- 次ターン開始時に再計算する

## 盤面座標

2×2盤面は以下で管理する。

```text
[ FrontTop    ][ BackTop    ]
[ FrontBottom ][ BackBottom ]
```

- Front = 前列
- Back = 後列
- Top = 上段
- Bottom = 下段
- 左が前、右が後ろ

## 操作仕様

- 左クリック：選択 / 決定
- ホバー：説明表示 / 技の対象マスプレビュー
- 右クリック：親メニューに戻る
- 空いている盤面をクリックしても何も起きない
- 味方や敵にホバーしても何も起きない

## コマンドUI

常に以下のどれかを表示する。

- 技一覧画面
- 交代画面
- アイテム画面

左側メインコマンド:

- Fight
- Swap
- Item

Fightを押すとSkill 1〜4を表示。Swapを押すと控え一覧を表示。Itemを押すとアイテム一覧を表示。一度Fightを押した後でも、SwapやItemに切り替え可能。

## 技仕様

- 各キャラは技を4つ持つ
- 技にホバーすると説明表示
- 同時に攻撃対象マスをハイライト
- 対象マスは現在操作中キャラの位置基準でリアルタイムに決まる
- 交代や回転で位置が変わると、対象プレビューも更新
- 技をクリックすると使用確定し、そのキャラの行動終了
- 技は拠点で複数候補から4つを選んで装備する。ポケモンの技選択に近い運用を想定
- 技はストーリー、イベント、レベルアップなどで増える想定

## 合体技仕様

- 合体技を導入予定
- 合体技は通常技と同じく、キャラの技枠4つのうち1つとして選択できる想定
- 例：キャラクターAの技3は、自身とキャラクターBが前衛にいることを条件に使用可能
- 合体技の条件には、特定キャラの存在、前衛配置、特定マス、特定バフなどを将来設定できるようにしたい
- 合体技は戦略性を上げる要素であり、見た目の派手な演出にも使う
- 初期実装では通常技を優先し、合体技は後から追加する

## 交代仕様

- 現在操作中キャラと控えキャラを交代する
- 控えをクリックすると即交代
- 交代は行動権を消費しない
- 交代後も技またはアイテムを使うまで行動終了しない
- 右クリックで交代前には戻さない
- 元に戻したい場合は、交代コマンドで元キャラを選び直す

## アイテム仕様

- 回復アイテムのみ
- 対象は操作キャラの前のマスにいる味方1人
- BackTopのキャラはFrontTopの味方に使用可能
- BackBottomのキャラはFrontBottomの味方に使用可能
- FrontTop / FrontBottomのキャラは前方マスがないため、そのままではアイテム使用不可
- アイテムを使用したら、そのキャラの行動終了

## 回転仕様

- 回転ボタンは味方盤面の近くに常設
- クリックすると味方陣を時計回りに90度回転
- 回転は行動権を消費しない
- 回転後、現在操作中キャラの位置と技対象プレビューを更新

## UI方針

画面構成:

- TopActionPanel
- CommandPanel
- EnemyGridPanel
- AllyGridPanel
- AllyStatusPanel
- TurnOrderBar
- BossNamePlate

バトルログは廃止。

敵盤面:

- 敵名のみ表示
- HPは表示しない
- 敵HPは下部行動順バーの小HPバーで表示
- HP数値は出さない

味方ステータス:

- 右側にコンパクト表示
- 顔アイコンのみ
- キャラ名は表示しない
- HP/MPはバーと数値付き
- バフ/デバフアイコン欄を置く
- 行動順数字は出さない

行動順バー:

- 下部に表示
- 敵味方混合
- 味方枠は顔アイコンと小HPバー
- 敵枠は敵種別アイコンと小HPバー
- 現在行動中は青枠
- 戦闘不能はグレーアウトし、SKIPまたは×表示
- ターン再計算時はスライド更新

## 行動演出中

行動確定後または敵行動中は、コマンドUIを操作不能にする。

画面上部中央に表示:

```text
1行目：使用技名
2行目：使用者名
```

攻撃元マスと対象マスを強調表示。無関係キャラは少し目立たなくする。攻撃時は使用者が少し前に出る。被弾時は対象キャラが小さく揺れる。

## 立ち絵ルール

- 各キャラはマス中央下を基準に立つ
- 頭や武器はマス外にはみ出してよい
- 足元はマス内に残す
- 描画順は下のマスほど前面
- 待機モーションは軽い上下揺れ、髪揺れ程度
- 操作中キャラは立ち絵を光らせる

## 戦闘不能・補充

- 空マスは薄いグリッドだけ残す
- 戦闘不能時は爆発して消える
- 味方が戦闘不能になった場合、控え一覧の上から順に自動補充
- 補充位置は倒れたキャラのマス
- 補充時は横からスライドイン

## バフ・デバフ

初期実装:

- 攻撃アップ
- 防御アップ
- 攻撃ダウン
- 防御ダウン

実装しない:

- 素早さアップ
- 素早さダウン
- 状態異常

ルール:

- 基本持続は2ターン
- 同じ効果は上書き
- 重複加算しない
- 同種の逆効果がかかった場合は打ち消して0に戻す

例:

- 攻撃アップ中に攻撃ダウン → 0に戻る
- 攻撃ダウン中に攻撃アップ → 0に戻る

## Codex運用ルール

Codexは制限があるため、通常相談には使わない。設計・判断・GitHub操作・Unity操作確認はChatGPT側で行う。

Codexを使うのは以下のみ。

- 複数ファイルのコード修正
- Unity C#スクリプト作成
- Editor拡張修正
- コンパイルエラー修正
- PR作成

Codexに依頼する時は必ず以下を指定する。

```text
目的：
対象ファイル：
変更禁止ファイル：
実装内容：
テスト：
出力：
```

PRを作る場合の確認条件:

```text
Can automatically merge
Files changed が想定通り
古いブランチ由来の余計な差分がない
```

Codexがpushできない場合:

```text
変更後ファイル全文を出力してもらい、手元で置き換える
```

## PROJECT_CONTEXT.md 更新運用

このチャットでは、重要な仕様決定・作業方針変更・トラブル対応方針が固まった場合、確認なしで `docs/PROJECT_CONTEXT.md` へ追記してよい。

ただし、追記の成功・失敗に関わらず、次の応答時に「PROJECT_CONTEXT.mdへ追記したか」「成功したか失敗したか」を伝える。

追記対象の例:

- 戦闘仕様の確定・変更
- UI仕様の確定・変更
- GitHub / Unity / Codexの運用ルール変更
- 作業ログとして残す価値がある失敗と対処
- 新規チャット移行に必要な前提情報

GitHubへの書き込みに失敗した場合は、代わりに追記案を本文で提示し、手元反映できる形にする。
