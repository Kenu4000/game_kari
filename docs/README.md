# docs

このディレクトリは、ゲーム制作中に決まった仕様・実装方針・レビュー結果を整理するための場所です。

## 基本方針

このチャットで仕様、実装方針、運用ルール、反省点、レビュー方針が固まった場合、必要に応じて `docs` 配下の該当ファイルを更新します。

会話内で決まった内容を一時的な口頭メモで終わらせず、再利用できる形で残すことを優先します。

## 分類

```text
docs/
├── design/
├── guidelines/
├── roadmap/
└── self-review/
```

### design

ゲーム固有の仕様、構想、設計意図を置きます。

例:

- 戦闘システム
- ゲームサイクル
- アクターが振る舞えること
- アイテム、ゴールド、報酬、成長
- マスタデータやDomainオブジェクトの設計意図

### guidelines

他プロジェクトにも流用できる実装ルール、デバッグ手順、レビュー手順を置きます。

例:

- コーディングルール
- デバッグ方法
- Unity / C# / GitHub の運用
- レビューガイドライン
- セルフレビュープロンプト

### roadmap

実装ロードマップを置きます。

親子関係は次の通りです。

```text
roadmap
└── phase
    └── task
```

### self-review

Claude Code と Codex のセルフレビュー結果、統合メモ、採用・不採用判断を置きます。

## 更新ルール

以下に該当する会話が発生した場合、必要に応じて該当docsを更新します。

- 仕様が確定した
- 仕様を変更した
- 実装方針を変更した
- 不具合原因と対処が明確になった
- 今後も使える実装ルールが見つかった
- レビュー観点が増えた
- roadmap上の作業単位が変わった

## 判断基準

```text
ゲーム固有の内容
→ docs/design/

他プロジェクトにも持ち越せる知見
→ docs/guidelines/

作業計画、phase、task
→ docs/roadmap/

AIレビュー結果、レビュー統合、修正判断
→ docs/self-review/
```

## 注意

`docs` は実装の後追いメモではなく、今後の実装判断に使う前提資料として管理します。
古くなった内容は、残すだけでなく更新・分割・移動します。
